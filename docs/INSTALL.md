# Установка перевода на ГУ Deepal S05 (fw 3.2.0)

Детальная инструкция: что где лежит, оба варианта установки, ручной режим
без `deepl`, проверка, снятие, локаль, частые проблемы.

Короткий путь (3 шага) уже в [README.md](../README.md) — этот документ
дополняет его. Работаем из папки с релизом (там и APK, и `deepl`,
и `targets.txt` — **всё из одного unzip'а**, без других папок).

## Состав папки

| Файл | Что |
|---|---|
| `apks_rro_min/` — 100 APK (+ `.idsig`) | **Динамические** RRO (пакеты `com.android.vendor.translate.rro.*`): ставятся как обычные приложения в `/data/app`, включаются/отключаются через `overlay enable` — без root-раздела |
| `apks_rro_static/` — 100 APK (+ `.idsig`) | **Статические** RRO (пакеты `com.deepal.translate.rro.*`): кладутся в `/vendor/overlay/`, активны с загрузки, сменяются только удалением |
| `deepl` / `deepl.exe` | менеджер RRO: ставит **обе схемы** — у каждой своё меню (`./deepl` — динамические, `./deepl stat` — статические). Выбор APK внутри обоих меню одинаковый |
| `shot` / `shot.exe` | снимок живого logcat + охота за runtime-фразами (те, что не в APK): `-q "фраза"`, `-cjk`, `-offline shot_*.log` |
| `targets.txt` | список приложений-целей для `deepl`. **Без него `deepl` не стартует** — не выкидывайте файл |
| `README.md` | этот файл (в zip — он же README) |

## Подключение ГУ (ADB)

1. ГУ → инженерное меню → включить **USB-отладку / ADB**.
2. Подключить по USB к PC.
3. Проверить: `adb devices` — строка `XXXX  device`.
   - `unauthorized` — публичный ключ adb этого ПК не добавлен на ГУ.
     Лечится **приложением `adbauth` на ГУ** (ставится заранее, пока adb
     доступен): скопировать `adbkey.pub` этого ПК на USB-флешку → на ГУ
     `adbauth` → «Добавить ADB-ключ с USB».
   - `no devices` — кабель/USB-порт/включение ADB.
4. В `deepl` устройство не видно → пункт **`[R] Проверить ADB заново`**
   (полная проверка + перезапуск демона). В шапке меню — баннер статуса ADB.

## Какие переводы и почему две схемы

- **Динамические** (обычный путь). `adb install` + `overlay enable`.
  Нюанс: на этом ГУ 9 оверлеев с целью AOSP-пакет **не ставятся**
  `adb install` (лимит подписи, `INSTALL_FAILED_INTERNAL_ERROR`) — поэтому
  реально устанавливается **91 из 100** (списки в `targets.txt` это знают).
- **Статические** — те же 100, включая 9 AOSP: ложатся в `/vendor/overlay`
  (нужен `adb root` + remount, `deepl stat` делает сам). Минус: только
  root и перезагрузка после установки; плюс: «зафиксированы», не зависят
  от `/data` (переживают сброс настроек пользователя).

Что переводится, что нет — переводятся **строки ресурсов** приложений
(102 приложения: экраны, меню, диалоги). Фразы, которых **нет в APK**
(runtime-сцены scene.db, TTS-ответы, ASR-команды) — не покрывает
ничего: их ловит `shot` (для поиска/переводчика).

## Установка (меню `deepl`)

```
./deepl                # Windows: deepl.exe (из папки с APK)
```

Меню:

```
[1] Установить + включить   (install + enable)
[2] Включить                (enable)
[3] Отключить               (disable)
[4] Удалить                 (disable + uninstall)
[5] Статус                  (что установлено/включено)
[6] Диагностика             (локаль, оверлеи, dump, dumpsys)
[7] Собрать логи            (report: zip для анализа)
[8] Перезагрузить ГУ        (adb reboot)
[9] Восстановить оригинальную локаль (zh-CN)
[R] Проверить ADB заново    (полная проверка + рестарт демона)
[0] Выход
```

После `[1]` — выбор **цели** (одинаков в меню dyn и stat):

```
[1] CRITICAL   [2] CORE UI   [3] IMPORTANT APPS   [4] SECONDARY
[8] TOP-8 (критичные 8)   [A] Все группы   [C] CORE+IMPORTANT (2+3)
[auto] Все *_RRO.apk из каталога схемы
[L] Пакеты по номерам (5 или 5,12 18)
```

**Рекомендация:** начать с `8` (TOP-8 — основные сцены + проверка),
затем `A` (всё). Для статических: `./deepl stat` → то же меню
(`[1] Установить` / `[2] Удалить` / `[3] Статус` / `[4] Диагностика`
/ `[5] Собрать логи` / `[6] Перезагрузить` / `[9]` / `[R]`).

CLI (без меню):

```
./deepl dyn install 8      # динам.: TOP-8 (install+enable)
./deepl dyn install A      # динам.: всё
./deepl stat install auto  # статические: всё (root+remount -> /vendor/overlay)
./deepl stat uninstall auto
./deepl dyn status         # состояние
./deepl dyn locale-restore # = меню [9]
./deepl report dyn|stat    # zip-отчёт
```

CLI-пресеты: `1|2|3|4`, `8` (TOP-8), `A` (все группы), `C` (2+3),
`auto` (все APK каталога), либо имена пакетов через пробел
(`./deepl dyn install Camera WT_NewLauncher`).

## Установка руками (adb, без `deepl`)

**Динамические:**

```bash
# ru-локаль в начало (перевод применяется только при ru в system_locales):
adb shell settings put system system_locales ru-RU,en-US,zh-CN

for f in apks_rro_min/*_RRO.apk; do
  app=$(basename "$f" _RRO.apk | tr '[:upper:]' '[:lower:]')
  adb install "$f"
  adb shell cmd overlay enable --user 0 com.android.vendor.translate.rro.$app
done
```

**Статические** (нужен root+remount; на части прошивок remount запрещён
(verity) — тогда только динамическое):

```bash
adb root && adb remount
for f in apks_rro_static/*_RRO.apk; do
  app=$(basename "$f" _RRO.apk | tr '[:upper:]' '[:lower:]')
  adb shell mkdir -p "/vendor/overlay/com.deepal.translate.rro.$app"
  adb push "$f" "/vendor/overlay/com.deepal.translate.rro.$app/"
done
adb reboot
```

> Имя пакета = префикс + имя APK в нижнем регистре (underscore остаётся):
> `WT_NewLauncher_RRO.apk` → `com.android.vendor.translate.rro.wt_newlauncher`.

## Проверка

- **В GUI:** открываем любое приложение (мультимедиа, центр авто,
  камера) — интерфейс по-русски.
- **Статус (меню `[5]`)**: по 100 пакетов — «УСТАНОВЛЕН / НЕ» +
  оверлей `[x]`/`[ ]`/`---`. Статика: папки в `/vendor/overlay`.
- **Локаль:** `adb shell settings get system system_locales` —
  должно быть `ru-RU,en-US,zh-CN`.
- **Report:** `[7] Собрать логи` → `logs/deepl_<scheme>_report_<TS>.zip`
  (`summary.txt` внутри — читать первым).

## Снятие / возврат как было

| Что | Как |
|---|---|
| Динам.: отключить (пакет остаётся) | `./deepl` → `[3]` (или `./deepl dyn disable A`) |
| Динам.: удалить всё | `./deepl` → `[4]` (или `./deepl dyn uninstall auto`) |
| Статич.: удалить всё | `./deepl stat` → `[2]` + reboot (или `./deepl stat uninstall auto`) |
| Локаль в `zh-CN` (как из коробки) | меню `[9]` / `./deepl dyn locale-restore` |

Собственно «перевод» = оверлеи + локаль: удалили оба — ГУ как было.

## Частые проблемы

| Симптом | Что делать |
|---|---|
| Меню `deepl` пусто/«targets» — ошибка | нет `targets.txt` в папке (или `DEEPL_TARGETS=/путь`) |
| ADB «не найдено» | `[R]` в меню; кабель/ADB; `unauthorized` — ключ adbkey.pub на ГУ приложением adbauth (см. «Подключение») |
| Пакет установлен, но китайский | `[3] Отключить` → `[1] Установить` снова (или reboot); проверьте `[5] Статус`, что оверлей `[x]` |
| Оверлей `---` (ошибка) | `[6] Диагностика`, `[7]` отчёт; изредка — `enable` ещё раз |
| Статика: remount не прошёл (`verity`) | только динамический вариант |
| `deepl` не видит `adb` | `adb.exe` в PATH, рядом с `deepl`, или `DEEPL_ADB=/путь/adb` |
| RU есть не во всём (например, детали «Умного обслуживания») | это данные с сервера (не ресурсы) — RRO не покрывает, остаётся как есть |
| Хочу перевести фразу, которой нет ни в одном экране в APK | она runtime (сцены/TTS/ASR): `shot -cjk -d 180` (показать сценарий), потом передать фразу переводчику |

## Примечания

- Перезапуск приложений: некоторые процессы увидят RU только после
  собственного перезапуска (закрыть из «недавних») либо reboot ГУ.
- Локаль переживает reboot (`settings.db`); оверлеи в `/data` — тоже;
  статика — намертво до удаления.
- `manage.bat` / `manage_static.bat` (старые баты) больше не идут с релизом —
  весь их функционал в `deepl` (и пункт `[9]`).
